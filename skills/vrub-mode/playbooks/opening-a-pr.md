### Opening a PR

For code or instruction changes that should be submitted. Read-only investigations and status checks do not open PRs.

Work from a git worktree off trunk, and keep unrelated work out of it. Rebase into small, landable commits. Before commit, run the **deslop** skill on code and the **unslop** skill on prose. Run `/no-comments` before review.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`.

**Push gate.** Every push to a branch with an open PR runs its CI, so open the PR at the code-ready head and push to it only at a green checkpoint. Before the push that opens or updates a PR, run the repo's local checks on the committed head. Use the pre-push check its AGENTS.md, CLAUDE.md, or rules name. Otherwise run its typecheck, lint, and the tests for the touched paths. Leave the full suites to CI when the repo says CI owns them, and never run a repo-wide check the repo tells agents not to run. A pre-commit hook pass is not proof. Fix a red check before the push, batch every known fix into one push, and never push to learn whether CI passes. When a verifier gates the PR, get its verdict on the local commit first, then push the exact SHA it passed. A later commit needs its own verdict, except a wording-only commit, and the patch-id rule in `playbooks/shipping.md` step 3 decides whether a verdict holds after a rebase.

A verify receipt is a record that the repo's verify command writes for one tree, for example under `$(git rev-parse --git-common-dir)/verify/<tree-hash>`, with the tree hash, the commands, and their exit status. A verifier checks the hash against `git rev-parse <sha>^{tree}` and treats a missing or mismatched receipt as no local proof. A verifier on another machine fetches a local commit from a scratch `<branch>-verify` branch with no PR, deleted after the verdict. A branch with no PR can be pushed as often as you like for backup.

Stack follow-ups by base branch. Open PRs ready, through the run's PR tool with `draft: false`. Without one, use `gh pr create` without `--draft`, or `origin pr create --status open` when Origin's CLI resolves the repository. Opening a PR does not start a watch or authorize a merge. If the user already asked to get the change green, continue through the `babysit` skill once the planned build work finishes, and through `ship` when the request includes merging. A subagent that opens a PR posts the URL and returns to its parent without babysitting, unless it is an Autopilot-full or Autopilot-stack owner, whose brief assigns the babysit loop.
